# Packed-tile DMA with direct 32-bit steering (PnR-legal baseline)

This revision changes the DRAM contract from the original HWC16 tensor layout
to software-packed source objects. The CPU passes a pointer to one packed
activation tile or one packed 8x8 weight slice. The DMA then amortizes DRAM
read latency across a complete row or slice instead of issuing one request for
every eight-byte destination group.

The external architecture remains:

- one CPU-facing AXI4-Lite slave;
- one read-only, 32-bit AXI4 master to off-chip DRAM;
- one four-byte `map_valid/map_ready` stream to a synthesizable NPU adapter;
- eight parallel 8-bit activation-SRAM write ports; and
- eight parallel 8-bit weight-shift lanes.

The complete hardware integration is provided by
`combined_dma_npu_sram_top.sv`. It instantiates `dma_a`,
`dma_npu_sram_adapter`, and the existing `npu_sram_wrapper`; SRAM writes are no
longer generated by testbench-only combinational logic.

## What changed

| Transfer | Previous AXI policy | Packed long-burst policy |
| --- | --- | --- |
| 1x1 activation tile | 256 two-beat requests | 16 row requests, 32 beats each |
| 3x3 activation tile | 289 two-beat requests plus 35 local zeros | 17 row requests, 34 beats each, plus the same 35 local zeros |
| One 8x8 weight slice | 16 one-beat requests with a word cache | One 16-beat request |

The useful beat count is unchanged; the number of address requests and DRAM
latency gaps is greatly reduced.

This patch also removes the 32-to-64-bit activation widening pipeline. The AXI
throughput remains one accepted 32-bit R beat per cycle.

The earlier experimental package explicitly instantiated
`FABULOUS_MUX2/4/8` for register- and I/O-driven selectors. That is not legal
for this FABulous architecture: nextpnr treats those BELs as LUT-cascade muxes
and requires every data input to come directly from a clustered LUT `O` port.
This baseline therefore expresses those selections as normal RTL and lets the
platform synthesis flow map them legally.

| Internal path | Previous implementation | This implementation |
| --- | --- | --- |
| Activation data | 32-bit half register plus 64-bit map register | Direct 32-bit R beat to four selected SRAM banks |
| Activation writes | Eight banks once per two beats | Four banks on every beat |
| Weight data | Shared 64-bit map register | One 32-bit low-half register in the weight adapter |
| Map masks | `8'hff` per eight-byte group | `8'h0f`, then `8'hf0`, at one shared destination address |

## Packed memory contract

Register `0x00` is now a pointer to the exact object for the current operation.
The AGU does **not** add tile, channel-block, kernel, or output-block offsets to
that pointer. Software chooses and packs the object, writes its pointer, and
then starts the DMA.

All data is byte-addressed and uses little-endian AXI word lanes.

### 1x1 activation object

Size: `16 * 16 * 8 = 2048` bytes.

```text
packed_offset(py, px, lane) = ((py * 16 + px) * 8) + lane
global_y = tile_y * 16 + py
global_x = tile_x * 16 + px
channel  = cin_block * 8 + lane
```

`py` and `px` are 0 through 15; `lane` is 0 through 7. Each 128-byte
row is fetched with `ARLEN=31`, meaning 32 returned 32-bit beats.

### 3x3 activation object

Size: `17 * 17 * 8 = 2312` bytes.

The packed object contains only the valid 17x17 spatial neighborhood. The DMA
expands it into the NPU's existing 18x18 activation map and inserts one zero
row and one zero column locally:

```text
packed_offset(py, px, lane) = ((py * 17 + px) * 8) + lane
global_y = tile_y * 15 + py
global_x = tile_x * 15 + px
channel  = cin_block * 8 + lane
```

For `tile_y=0`, the zero row is inserted before the packed rows; for
`tile_y=1`, it is inserted after them. `tile_x` controls the zero column in
the same way. This is the current fixed 32x32 image split into four 16x16
tiles. Each 136-byte valid row is fetched with `ARLEN=33`, or 34 beats.

### Packed 8x8 weight slice

Size: `8 * 8 = 64` bytes and required alignment: 64 bytes.

The bytes are stored in the order consumed by the weight shifter:

```text
packed_offset(shift, lane) = shift * 8 + lane
input_channel  = cin_block * 8 + lane
output_channel = cout_block * 8 + (7 - shift)
```

Thus group zero contains output column seven for all eight PE rows, and group
seven contains output column zero. The complete slice is one `ARLEN=15`
request followed by 16 returned 32-bit beats. Software must transpose/reorder
the original `[input_channel][output_channel]` tensor into this format.

## Direct 32-bit datapath and backpressure

`combined_hwc_channel_dma_agu` now emits one descriptor per packed activation
row and one descriptor per weight slice. `dma_a` issues the corresponding
AXI INCR request and accepts R beats on consecutive cycles whenever the NPU
side can keep up.

For a fetched activation, `map_data[31:0]` is the current AXI R beat. The
first beat of a group carries `map_bank_mask=8'h0f`; the next carries
`8'hf0`. Both carry the same `map_buffer_addr`, and that address advances
only after the high-bank beat is accepted. There is no activation data FIFO,
half-word register, or 64-bit output register.

During a DRAM-backed transfer, `map_ready` directly qualifies AXI `RREADY`.
If ownership is withdrawn, the AXI slave is required to retain its current
R beat, so `map_data` and its metadata stay stable without local widening
storage. Local zero-padding beats are held by the DMA state machine in the
same way. The weight adapter retains only the first 32-bit beat because the
existing NPU weight port still consumes eight lanes in one shift event.

Every low/high pair remains one architectural eight-channel group. Direct
steering therefore sustains the same four-byte-per-cycle source rate as the
old widening path while removing the 64-bit map register and its selection
logic.

Only one AXI burst is outstanding. The RTL tolerates arbitrary `ARREADY`,
`RVALID`, and `map_ready` stalls; consecutive R beats are not assumed even
though a normal DRAM controller will usually provide them inside a burst.

### AXI 4 KiB rule

Activation pointers must be eight-byte aligned. If a packed activation row
would cross a 4 KiB boundary, the DMA automatically divides that row into two
legal contiguous bursts and continues assembling the same output stream.

Weight pointers must be 64-byte aligned. A 64-byte slice then cannot cross a
4 KiB boundary, guaranteeing one 16-beat weight burst.

## CPU AXI4-Lite programming interface

| Address | Access | Meaning |
| --- | --- | --- |
| `0x00` | W | Write packed-object byte pointer and start. |
| `0x00` | R | Last accepted packed-object pointer. |
| `0x04` | R | Bits `[2:0]` are `{error_sticky, busy, done_sticky}`. |
| `0x08` | W/R | Operation configuration. |

Configuration register `0x08`:

| Bits | Field | Hardware use in packed mode |
| --- | --- | --- |
| `[0]` | `tile_x` | Selects whether 3x3 zero padding is before or after each row. |
| `[1]` | `tile_y` | Selects whether the 3x3 zero row is before or after valid rows. |
| `[2]` | `cin_block` | Software bookkeeping; does not offset the pointer. |
| `[3]` | `load_weight` | 0 = activation object, 1 = packed 8x8 weight slice. |
| `[4]` | `cout_block` | Software bookkeeping; does not offset the pointer. |
| `[6:5]` | `kernel_y` | Bookkeeping and 3x3 range validation; no pointer offset. |
| `[8:7]` | `kernel_x` | Bookkeeping and 3x3 range validation; no pointer offset. |
| `[9]` | `conv_1x1` | 0 = 3x3 schedule, 1 = 1x1 schedule. |

Example:

```c
// Software has packed this 1x1 tile/channel block at packed_tile_ptr.
config = (1u << 9) | (cin_block << 2) |
         (tile_y << 1) | tile_x;
write32(DMA_BASE + 0x08, config);
write32(DMA_BASE + 0x00, packed_tile_ptr);  // starts the DMA

// Software has packed one 8x8 slice in shift order at packed_weight_ptr.
config = (kernel_x << 7) | (kernel_y << 5) |
         (cout_block << 4) | (1u << 3) | (cin_block << 2);
write32(DMA_BASE + 0x08, config);
write32(DMA_BASE + 0x00, packed_weight_ptr); // 64-byte aligned
```

Poll status bit 0 for completion. Bit 1 is busy and bit 2 is the sticky error.
A start/configuration write while busy, an invalid 3x3 kernel coordinate, or a
misaligned pointer returns `SLVERR`. A successful later start clears the done
and error sticky bits.

An AXI `RRESP` error sets `error_sticky`, substitutes zero for that failed
32-bit beat, and lets the operation finish. Incorrect `RLAST` timing also sets
the sticky error.

## Destination stream

One accepted `map_valid/map_ready` transfer contains:

- `map_data[31:0]`: four source bytes;
- `map_buffer_addr`: activation SRAM address or weight shift index;
- `map_bank_mask`: `8'h0f` for banks 0--3, then `8'hf0` for banks 4--7;
- `map_is_weight`, `map_zero_fill`, and `map_last`; and
- packed source address/stride metadata for checking and debug.

`map_source_addr` is the exact address of the current four-byte beat and
`map_source_stride` is one. `map_last` is asserted only on the high-bank beat
of the final group. After the eighth weight group, the existing disabled
shift cycle and one-cycle `map_weight_swap` pulse are preserved.

## Activation SRAM and weight-port ownership

`dma_npu_sram_adapter.sv` connects the destination stream directly to the
ports exposed by `npu_sram_wrapper`.

For an accepted activation beat (`map_valid && map_ready &&
!map_is_weight`), four banks receive writes:

```systemverilog
bank_base = map_bank_mask[7:4] != 0 ? 4 : 0;
for (lane = 0; lane < 4; lane++) begin
    bank = bank_base + lane;
    ext_act_sram_we[bank]    = map_bank_mask[bank];
    ext_act_sram_addr[bank]  = map_buffer_addr;
    ext_act_sram_wdata[bank] = map_data[lane*8 +: 8];
end
```

Thus the low beat writes banks 0--3 and the high beat writes banks 4--7 on
the following cycle at the same address. This is four independent 8-bit SRAM
writes per cycle and eight writes per complete group.

For weights, the low beat is captured in one 32-bit register. On the accepted
high beat, all activation write enables remain zero and the adapter drives:

```systemverilog
weight_shift_en    = 1'b1;
weight_shift_in[3:0] = saved_low_beat;
weight_shift_in[7:4] = current_high_beat;
```

The adapter has separate `dma_act_port_grant_i` and
`dma_weight_port_grant_i` inputs. Its handshake is:

```systemverilog
act_owned    = dma_act_port_grant_i    && !array_en;
weight_owned = dma_weight_port_grant_i && !array_en;
map_ready    = map_is_weight ? weight_owned : act_owned;
```

This distinction is important: an activation-only grant cannot acknowledge
and discard a weight map, and a weight-only grant cannot acknowledge and
discard an activation map. `array_en` is also a hardware interlock. While the
systolic array is active, `map_ready`, every activation write enable, and
`weight_shift_en` are forced low; activation addresses come from
`act_compute_addr` instead of the DMA.

The accelerator controller must follow this sequence:

1. Deassert `array_en` and wait until the current compute cycle is complete.
2. Assert the grant matching the requested DMA operation.
3. Program the DMA configuration and packed-object pointer/start register.
4. Retain the grant until DMA status reports done. For weights, this includes
   the disabled shift cycle and `swap_weights` pulse after the eighth group.
5. Deassert the DMA grant before asserting `array_en` for computation.

If ownership is withdrawn during a transfer, the map remains valid and AXI R
is backpressured; no fetched data is retired or written to the wrong port.

## FABulous cascade-mux resources

The reported `FABULOUS_MUX2/4/8` resources are not general-purpose substitutes
for RTL muxes. In nextpnr's FABulous packer, a MUX2 is clustered with two LUTs,
a MUX4 with four LUTs, and a MUX8 with eight LUTs. Every mux data input must be
driven by the `O` output of one of those LUT/COMB cells. A direct connection
from a register, AXI BEL, constant, or module port causes packing to fail with
`input I<n> ... is not driven by a LUT`.

Consequently, this source set contains no manual `FABULOUS_MUX2/4/8`
instances and no `fabulous_mux_cells.v`. The correct way to exploit those
resources is an architecture-aware wide-LUT synthesis mapping: identify logic
cones wider than the base LUT, implement their leaves in clustered LUTs, then
use the cascade mux above them. Adding pass-through LUTs in front of ordinary
2:1 register muxes would generally increase, not reduce, LC usage.

After regenerating the JSON used by nextpnr, check that no primitive from the
old manual experiment remains:

```bash
make -f Test/combined_1x1_3x3_dma/Makefile.dma_combined pnr-mux-check \
  SYNTH_JSON=user_design/combined_1x1_3x3_dma/combined_hwc_channel_dma_agu.json
```

The legacy `mux-usage` target is retained as an alias for this check. Override
`SYNTH_TOP` if the platform uses a different synthesis top name. Then rerun
place-and-route and compare `FABULOUS_LC` against the pre-direct-steering
baseline; the cascade-mux count is expected to be zero until the synthesis
flow gains a legal architecture-aware mapper.

For the FABulous interactive shell, first copy this package's isolated
`top_wrapper.v` to the framework-managed `user_design/top_wrapper.v`. Do not
also list either `top_wrapper.v` or the removed `fabulous_mux_cells.v` as a
design source. Regenerate the JSON before using `--pnr-only`:

```text
(Cmd) load_fabric
(Cmd) compile_design user_design/combined_1x1_3x3_dma/combined_hwc_channel_dma_agu.sv user_design/combined_1x1_3x3_dma/dma_a.v -top top_wrapper -json user_design/combined_1x1_3x3_dma/combined_hwc_channel_dma_agu.json --synth-only
(Cmd) compile_design user_design/combined_1x1_3x3_dma/combined_hwc_channel_dma_agu.sv user_design/combined_1x1_3x3_dma/dma_a.v -top top_wrapper -json user_design/combined_1x1_3x3_dma/combined_hwc_channel_dma_agu.json --pnr-only
```

The first command overwrites the stale JSON that contained the illegal mux
instances. Running only the second command against that stale JSON will repeat
the same nextpnr packing error even after the RTL files have been replaced.

## `top_wrapper.v`

The supplied FABulous `top_wrapper.v` remains an **isolated DMA placement and
resource-estimation wrapper**. It contains one `AXIL_S_BEL`, one `AXI_M_BEL`,
and a deliberate always-ready synthetic sink. It does not contain the NPU
controller signals required to instantiate the SRAM subsystem and must not be
used as the deployed accelerator top.

For the real accelerator, instantiate `combined_dma_npu_sram_top.sv` below the
platform AXI BELs and connect its two grant inputs plus the existing NPU
controller ports. Then regenerate or patch the platform-specific FABulous top
around that payload. This avoids tying `map_ready` high in hardware and avoids
inventing values for `array_en`, crossbar selects, compute addresses, and PSUM
controls in a generated placement wrapper.

The AXI master placement used by the isolated reference wrapper is `X11Y6.A`;
confirm that coordinate against the target `fabric.csv` or generated BEL list
before place-and-route.

## Simulation

From the repository root:

```bash
make -f Test/combined_1x1_3x3_dma/Makefile.dma_combined clean
make -f Test/combined_1x1_3x3_dma/Makefile.dma_combined packed-check
make -f Test/combined_1x1_3x3_dma/Makefile.dma_combined ownership-check
```

`packed-check` runs the independent Python model and standalone RTL regression.
`ownership-check` is an explicit alias for the standalone RTL regression that
removes the relevant grant and asserts `array_active` during transfers. It
checks that `map_ready` drops, map metadata remains stable, compute addresses
are restored, and no SRAM write or weight shift occurs without acceptance.
The model covers all 16 activation configurations and 40 weight configurations:
4960 destination groups, 9920 direct map beats (including local zeros), 280
local-zero groups, 304 long bursts, and 9360 DRAM AXI beats. Both the model
and standalone RTL regression exercise an activation row split at a 4 KiB
boundary.

Run the full one-reset NPU regression with:

```bash
make -f Test/combined_1x1_3x3_dma/Makefile.dma_combined integrated
```

The integrated test converts the original image and weight vectors into the
packed DRAM address view inside the testbench, then checks both complete output
tensors against the original golden memories.
